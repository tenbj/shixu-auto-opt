01 / 一套业务入口

人和 AI 使用相同规则

浏览器、API 调用方和 MCP 最终汇入 FastAPI。MCP 负责工具协议与 HTTP 适配；状态流转、依赖校验与持久化均由后端处理。

02 / 写入如何保持一致

版本 + 行锁 + 幂等

调用方携带 expected_version 和 request_id。后端先锁定 workspace_meta(owner_id)；重复同指纹请求返回已保存响应，否则检查版本、执行规则并提交。

版本冲突返回 409；数据库失败返回 503。事务出错则回滚。

03 / 数据在哪里

实体、审计都保存在 MySQL

20张表的DELETE触发器阻止物理删除；应用运行时拒绝DELETE/TRUNCATE/DROP/REPLACE。行动依赖移除也保留行，仅筛选有效关联。问题和行动保存 deleted_at、deletion_batch、deleted_with_issue。普通列表过滤回收站；恢复校验父问题、同批记录与有效依赖。正式库使用独立 schema。读取时从表中组装请求快照；服务重启后仍从 MySQL 读取。身份登记保存在MySQL；浏览器仅保存当前身份ID与布局偏好。创建人、提交者、来源、模型、UTC时间为创建快照。

SQLite 适配器用于隔离测试及旧数据迁移来源。MySQL 联调使用独立的 _test 库。

04 / 运行边界

容器部署与授权边界

HTTPS/FRP入口保持不变，转发宿主回环8765至单个非root应用容器。页面、API、MCP、双图、OAuth、接入资料与Skill下载随镜像交付。业务和认证状态保留在现有远程MySQL，runtime使用命名卷；秘密只在运行时注入。MCP经ASGITransport复用本进程API。镜像可替换，生产库不初始化或播种。

账号会话Cookie与CSRF，OAuth S256 PKCE、网页PAT；API/MCP均从认证上下文取得owner。只读范围、过期和撤销逐次检查，业务对象不可跨账号访问。actor及creation是来源声明，不决定归属。

显式开启HTTP兼容后，网页登录和PAT/API/MCP支持HTTP与HTTPS。HTTP明文传输；标准OAuth仍需HTTPS。HTTPS入口经可信代理标记识别。无管理员或共享工作台。

另有9张账号与授权表：app_users、account_sessions、account_access、oauth_clients、oauth_codes、oauth_pending、account_login_limits、access_metadata、oauth_refresh_tokens。逻辑owner关联由应用校验，ER图仅画6个真实物理外键。

AI快速接入

/connect、/connect.md、manifest与固定版本Skill下载向新设备提供公开引导。AI配置目标runtime，用户亲自登录授权；get_connection_context核对当前工作台与权限。设备证据区分授权、最近访问和MCP验证；runtime/Skill版本为自报。客户端完整实机验收范围见支持矩阵。

账号与接入边界

账号拥有独立工作台；旧数据归test，创建来源快照保留。会话使用HttpOnly Cookie与CSRF；密码使用scrypt。MCP令牌/OAuth授权码按账号和读写范围管理，逐次校验撤销。

OAuth：发现 → 注册客户端 → 登录确认 → S256 PKCE一次性授权码 → 访问令牌与轮换刷新令牌（最长30天）。公网HTTP兼容用于会话与PAT；OAuth保持HTTPS要求。双协议使用独立Cookie，HTTPS启用Secure；代理头仅接受明确可信来源。旧全局密钥不再接收。

账号关联为应用级逻辑关系，物理ER保留真实6个外键；20表保留物理删除防护。
