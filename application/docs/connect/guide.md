# 拾序 AI 接入指南

本指南供用户明确要求配置拾序的AI执行。公共内容不包含登录信息。服务接口3.2.0，Skill {{SKILL_VERSION}}。

1. 识别当前操作系统、运行环境及实际版本、是否能联网和写文件。先读取 {{BASE}}/connect/manifest.json ，再获取当前runtime的同源适配说明。只操作用户指定客户端。没有客户端则引导用户从官方入口安装；没有执行能力则生成配置供用户导入。
2. 检查已有MCP与Skill配置；用户要求更新时先读取 {{BASE}}/connect/updates.md 并按差异更新。优先原生Streamable HTTP，地址 {{MCP}}。合并新增shixu项，保留其他服务；若同名地址或账号不同，说明冲突并让用户选择，不覆盖。配置前备份，重复执行不重复追加。
3. 从版本清单skill.url下载固定版本Skill ZIP（SHA256 {{SKILL_SHA256}}），核对摘要后检查文件路径，拒绝绝对路径和父目录穿越。包包含SKILL.md、VERSION、业务references及可选的标准库更新脚本scripts/update.py；先校验再执行。按当前客户端支持的用户级Skill位置安装或通过其技能导入界面导入。若已有同版本且内容一致则复用；有用户修改则保留并解释差异。原生MCP不需要Python、Node、Git或拾序源码。
4. 优先客户端原生OAuth登录，由用户在拾序页面输入密码并确认账号、读写权限。访问令牌1小时，刷新令牌自动轮换、最长30天；撤销或刷新过期后重新授权。客户端不兼容OAuth时，让用户进入拾序右上角“AI接入→手动配置”生成独立访问令牌，在客户端私有配置入口完成交付。不得要求用户把秘密粘贴进聊天，不读取客户端凭据文件。
5. 需要重载或新会话时明确说明，并在用户私有数据目录保存非秘密接入进度（地址、目标runtime、已完成步骤、Skill版本），不把未加载标为连接成功。恢复后确认当前会话工具目录中出现shixu工具。
6. 调用get_connection_context（可传runtime_name、runtime_version、skill_version），核对账号与scopes，再list_issues。服务器只能证明这次MCP调用已认证；客户端和Skill版本为自报，必须在runtime内确认技能能被发现。分别报告已下载/配置/授权/加载/工具可调用/Skill可发现。只读授权不能记录问题，不能替用户扩大权限。
7. 默认不创建测试问题。用户明确给出记录请求时，按shixu-issues Skill分类、查重、确认来源、持久化幂等请求，调用create_issue并get_issue回读。模型来自可信运行信息或用户本次确认，不从工具品牌推断。

401恢复登录；403检查范围；网络中断保留原请求；不通过其他账号绕过权限。只向同源清单中的地址发送接入请求，不向第三方传递令牌。HTTP入口保留为兼容方式，但上述自动接入优先HTTPS。

## 验证边界

服务端API/MCP协议测试与runtime实机验收分开。清单verifiedVersions为空表示没有已验收客户端版本；documented只表示有官方文档依据。配置写入成功不能替代工具实际调用。没有可用能力时准确报告阻塞步骤和最小人工操作。
