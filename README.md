# 拾序 · 个人问题与行动工作台

> 把困扰理清，把今天过好。

版本：1.1.0 · 离线交互原型

拾序帮助个人记录问题痛点，把问题拆成下一步行动，并在行动完成后验证是否真正改善。

## 立即体验

1. 下载本仓库（Code → Download ZIP）并解压。
2. 用现代浏览器打开 `prototype.html`。
3. 从“随手记”开始，也可以编辑页面中的虚构示例。

无需安装依赖或启动后端。GitHub 文件页展示的是源码，需下载后在浏览器中打开。

## 四个工作视图

| 视图 | 用途 |
|---|---|
| 今日概览 | 聚焦今天和逾期的未完成行动 |
| 问题池 | 记录背景，搜索、筛选和梳理痛点 |
| 行动看板 | 在待办、进行中、已完成和已取消之间管理行动 |
| 复盘记录 | 保存验证结论，问题复发时重新打开 |

一个问题可以关联多个行动，行动也可以独立创建。全部行动完成不会自动解决问题；仍需填写验证依据。

## 问题状态

新问题默认进入 **待梳理**，记录时只需填写标题。

**待梳理 → 待处理 → 处理中 → 待验证 → 已解决**

- 梳理后补充下一步与解决标准，再开始处理。
- 支持暂缓并设置回看日期；恢复时回到暂缓前的阶段。
- 支持关闭、重复问题关联与重新打开，流转原因保留在问题动态中。
- 关闭前需取消或转为独立待办，避免未完成行动悬空。
- 本轮必要行动完成后才能提交验证；填写验证结论后才算解决。
- 问题卡片展示状态，问题池支持按七种状态筛选。
- 沿用原本的本地存储位置；旧记录在读取时补齐新字段，保留原内容和状态。

## 数据与边界

- 记录保存在当前浏览器的本地存储中，支持 JSON 导出。
- 更换浏览器、文件位置或清除浏览器数据可能导致原记录无法访问，请定期导出。
- 本版不提供 JSON 导入、登录、多设备同步或服务端。
- 初始内容为虚构演示数据，不含真实业务记录。
- `api.yaml` 和 `database.sql` 是后续工程设计合同，不代表后端已实现。

## 验证

50 项检查通过，覆盖七状态主流程、暂缓恢复、关闭与待办处置、重新打开、旧记录兼容、刷新持久化、搜索筛选、导出、存储失败提示和 390px 移动布局。

`evaluation/browser-test.js` 是浏览器评估函数；请在独立测试浏览器中运行，不要使用存有真实记录的浏览器。完整 50 项报告包含额外的刷新、兼容和移动布局检查，可查看 `evaluation/workflow-report.json`。

结构报告由设计阶段的 HH02 验证器生成。该工作区工具不包含在仓库中，不影响直接打开原型。
